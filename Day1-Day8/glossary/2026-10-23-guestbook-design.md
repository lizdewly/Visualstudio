## 질문

Day1~Day8의 문법과 알고리즘을 분석하여 기본 방명록 앱을 구현하고 싶다. 기존 기술을 최대한 유지하고, 필요한 라이브러리나 알고리즘은 먼저 물어본다. JavaScript 등 복잡한 화면 기술을 사용하지 않고 HTML 위주로 구성한다. Python 내장 DB에 관계 없는 테이블 하나만 사용하며, 무료 배포 서비스와 절차도 확인한다. 코드와 출력은 Day1-Day8에 저장한다.

## 답변

기존 FastAPI·Pydantic·Uvicorn과 함수, 조건문, 반복문을 활용할 수 있다. 메모리 딕셔너리 대신 Python 표준 라이브러리 `sqlite3`로 글을 파일에 저장한다. 테이블 하나에 글 번호, 이름, 내용, 작성 시각을 두는 안이다.

HTML form은 JavaScript 없이 서버에 등록 요청을 보낼 수 있다. FastAPI의 Form을 사용하려면 `python-multipart` 추가가 필요해 사용 확인 대상으로 정했다. 입력값을 검증한 뒤 SQL로 저장하고 목록으로 이동하며, HTML 특수문자를 글자로 표시하는 방법과 페이지별 조회도 제안했다. 최초 답변 시점에는 분석과 설계 문서만 작성하고 승인을 기다렸다. 이후 승인과 구현 결과는 아래에 이어 기록한다.

## 헷갈리기 쉬운 점

- HTML 화면을 사용해도 글 저장에는 Python 서버가 필요하다.
- SQLite는 Python 표준 라이브러리로 사용할 수 있지만 SQL 저장·조회 방법은 새로 익혀야 한다.
- 로컬 파일 저장과 무료 호스팅에서의 영구 보존은 다르다. Render Free는 재시작 등에 따라 파일이 사라진다.
- PythonAnywhere는 SQLite를 제공하지만 FastAPI용 ASGI 기능이 베타이므로 장기 무료 보장을 단정하지 않는다.
- Day5 폴더는 실제 작업 공간에 없었다. 원본 학습 코드의 일부 오류를 발견했지만 이 작업에서 수정하지 않았다.

## 후속 질문과 답변

### 2026-10-23: 승인한 구성으로 구현

질문: 위 패키지와 SQL 저장·조회, HTML 특수문자 처리, 등록 후 목록 이동 방식으로 구현을 진행해.

답변: 승인한 구성으로 `main.py`, HTML·CSS, 의존성 파일과 테스트를 만들었다. 새 외부 패키지는 `python-multipart`이며, 기존 FastAPI·Pydantic·Uvicorn을 유지했다. SQLite의 `guestbook` 테이블 하나에 이름·내용·작성 시각을 저장하고 글 번호를 기본 키로 사용한다.

정상 등록은 303 응답으로 목록으로 이동한다. SQL에는 `?` 매개변수로 값을 전달하고, HTML에 출력하기 직전에는 `html.escape`를 적용한다. 입력 오류는 422, 최대 1,000개 초과는 409로 안내하며 기존 데이터를 보존한다. 페이지당 10개를 최신순으로 조회한다.

구문 검사와 28개 테스트를 통과했고 Chrome에서 실제 폼 등록과 좁은 화면을 확인했다. 기본 데이터 파일은 `data/guestbook.db`이고 가상 환경의 Python으로 `main.py`를 실행한다. 외부 무료 서비스에 배포한 상태는 아니다. [실행 방법](../README.md), [검증 기록](../VERIFICATION.md)을 참고한다.
