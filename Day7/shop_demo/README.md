# 장바구니 연구소

상품의 재고·배송·리뷰를 조회하는 쇼핑몰 화면으로 동기와 비동기를 비교합니다.
기존 Day_7 파일을 바꾸지 않는 독립적인 로컬 앱입니다. 외부 API, 실제 결제, DB는 사용하지 않습니다.

## CMD에서 실행

프로젝트 루트에서 한 줄씩 입력합니다. 기존 실습과 포트가 겹치지 않도록 8010번을 사용합니다.

```bat
cd /d "C:\Users\김세원\Visualstudio"
.venv\Scripts\activate.bat
python -m uvicorn app:app --reload --app-dir Day_7\shop_demo --host 127.0.0.1 --port 8010
```

브라우저에서 **http://127.0.0.1:8010** 을 여세요. HTML 파일을 직접 여는 대신 서버 주소로 접속해야 합니다.
서버 종료는 이 CMD 창에서 `Ctrl+C`입니다. 앱은 워커 1개를 기준으로 실험합니다.

`No module named ...`가 나오는 경우에만 같은 가상환경에서 설치하고 다시 실행합니다.

```bat
python -m pip install fastapi uvicorn httpx
```

8010 포트가 사용 중이면 `--port 8011`로 바꾸고 브라우저도 http://127.0.0.1:8011 로 접속하세요.
웹 화면은 같은 서버의 상대 주소로 요청하므로 자동으로 새 포트를 사용합니다.
아래 콘솔 probe는 `base_url`의 포트를 별도로 수정해야 합니다.

## 화면에서 실험

1. 대기 시간을 1초로 설정하고 **동기 · 순차**를 실행합니다. 세 조회가 하나씩 끝나므로 전체 약 3초입니다.
2. **비동기 · 동시**로 바꾸고 실행합니다. 각 작업은 1초를 기다리지만 대기가 겹쳐 전체 약 1초입니다.
3. **서버 막힘**으로 바꾸고 조회 버튼을 누른 직후 **서버 응답 확인**도 누릅니다. 상태 확인 응답도 조회가 끝날 때까지 밀립니다.
4. 동기 · 순차 모드에서도 같은 실험을 해 보세요. FastAPI가 일반 `def`를 스레드풀에서 처리하므로 상태 확인은 빠르게 돌아올 수 있습니다.

| 모드 | 코드 | 조회 3개 | 상태 확인 |
| --- | --- | --- | --- |
| 동기 · 순차 | `def` + `time.sleep` + `for` | 대기 시간의 합 | 다른 스레드에서 처리 중이므로 루프가 응답 가능 |
| 비동기 · 동시 | `async def` + `await asyncio.sleep` + `gather` | 가장 긴 대기에 가까움 | 루프가 응답 가능 |
| 서버 막힘 | `async def` + `time.sleep` + `for` | 대기 시간의 합 | 루프가 막혀 응답 지연 |

동기와 순차, 비동기와 동시는 같은 말이 아닙니다. 이 앱에서 비교하기 위해 조합한 방식입니다.
`await`를 하나씩 차례로 쓰면 비동기 함수도 순차 실행됩니다. 동기 작업도 스레드 등을 사용하면 동시에 진행할 수 있습니다.

타임라인은 서버의 `perf_counter()` 측정값으로 **응답 후** 그립니다. 실행 중 진행도를 추정해 그리는 화면이 아닙니다.
브라우저 왕복 시간은 통신과 처리 대기를 포함하므로 서버 측정과 차이가 납니다. 기록은 현재 화면의 메모리에 최대 12개만 보관하며 새로고침하면 사라집니다.
상태 확인 버튼을 조회가 끝난 뒤 누르면 서버 막힘 모드에서도 빠르게 응답합니다. 기다림을 보기 어렵다면 조회당 2초를 선택하세요.

## 파일과 학습 순서

1. `app.py`: `lookup_sync`, `lookup_async`를 비교하고 세 API 경로의 호출 방법을 읽습니다.
2. `static/index.html`: 상품 카드, 조회 버튼, 측정 결과 화면입니다.
3. `static/app.js`: `fetch`로 API를 호출하고 실제 결과를 표시합니다. Python의 HTTPX와 비슷한 요청 역할입니다.
4. `static/style.css`: 반응형 화면 디자인입니다.
5. `probe.py`: HTTPX로 동일 API를 호출해 터미널에서 비교합니다.

재고·배송·리뷰 데이터는 고정 예시이며, `sleep`으로 외부 서비스의 응답 대기를 흉내 냅니다.
실제 비동기 HTTP 호출에서는 `httpx.AsyncClient`와 `await client.get(...)` 등을 사용합니다.
이 앱의 서버 막힘 모드는 원인을 체험하기 위한 의도된 나쁜 예입니다.
