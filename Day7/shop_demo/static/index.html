각 방식을 한 번씩 실행해 보세요.
01

순차 처리 ≠ 서버 전체 정지

일반 def 경로는 FastAPI의 스레드풀에서 실행됩니다. 한 요청 안에서는 순서대로 기다려도 다른 요청은 처리할 수 있습니다.

02

await + gather로 대기 겹치기

각 조회가 빨라지는 것이 아닙니다. 기다리는 시간을 겹쳐 전체 시간을 줄입니다. async라는 이름만으로 동시 실행되지는 않습니다.

03

실험은 단일 워커 기준

async 경로 안의 time.sleep은 이벤트 루프를 막습니다. 세 번째 모드에서 상태 확인도 늦어지는 이유입니다.
