## 답변

웹사이트는 보통 브라우저가 서버에 요청을 보내고, 서버가 돌려준 HTML·CSS·JavaScript·데이터 등을 브라우저가 처리해 화면으로 보여 주는 구조다. 하나의 화면을 위해 여러 요청이 발생할 수 있다.

| 용어 | 의미와 역할 | 비유 |
| --- | --- | --- |
| 클라이언트 | 서버에 요청을 보내는 프로그램. 브라우저나 HTTPX 코드 등 | 손님 |
| 서버 | 요청을 받아 응답하는 프로그램. 문맥에 따라 그 프로그램이 실행되는 컴퓨터를 뜻하기도 함 | 요청을 처리하는 가게 |
| IP 주소 | 네트워크에서 통신 목적지를 지정하는 숫자 주소 | 건물 주소 |
| 포트 | 한 호스트 안에서 통신할 서비스를 구분하는 번호 | 가게의 출입구 번호 |
| 도메인 | 사람이 기억하기 쉬운 이름. 예: `example.com` | 건물 이름 |
| DNS | 도메인에 해당하는 IP 주소 등을 조회하는 시스템 | 주소 안내부 |
| URL | 통신 방식, 호스트, 경로 등을 포함하는 자원의 주소 | 상세 방문 주소 |
| HTTP·HTTPS | 웹 요청·응답의 통신 방식. HTTPS는 TLS로 보호되는 HTTP | 대화 규칙 |
| WWW | World Wide Web. 인터넷 위에서 웹페이지와 자원을 연결하고 이용하는 시스템 | 웹 전체 |

IP와 건물의 비유는 입문용이다. 실제로 한 컴퓨터가 여러 IP를 쓰거나, 여러 웹사이트가 같은 IP를 공유할 수도 있다.

인터넷은 여러 네트워크를 연결한 기반이고, 웹은 그 위에서 사용하는 서비스 중 하나다. 이메일 등도 인터넷을 이용한다. `www.example.com`의 `www`는 관례적인 하위 도메인 이름이다. 모든 웹 주소에 필수인 것은 아니며, `example.com`과 같은 사이트로 연결할지는 운영자가 설정한다.

## 예제

```text
http://127.0.0.1:8000/health
│      │         │    └─ 경로: 어떤 기능을 요청할지
│      │         └────── 포트: 8000번 서비스
│      └──────────────── IP: 지금 요청하는 내 컴퓨터
└─────────────────────── 방식: HTTP
```

`127.0.0.1`은 자기 자신을 가리키는 특별한 IPv4 주소(루프백)다. 브라우저와 서버가 같은 컴퓨터에 있을 때 실습에 사용한다. `localhost`도 보통 자기 컴퓨터를 가리키며, 환경에 따라 IPv6 주소 `::1`로 연결될 수도 있다.

`8000`은 실습 서버가 요청을 기다리는 포트다. 반드시 8000이어야 하는 것은 아니고 서버 설정과 URL이 일치해야 한다. HTTP 기본 포트는 80, HTTPS 기본 포트는 443이므로 일반적인 웹 주소에서는 생략된다.

현재 `Day_7/main.py`에는 다음 코드가 있다.

```python
@app.get("/health")
def health():
    return {'status': 'ok'}
```

서버가 해당 주소에서 실행 중이라고 가정할 때의 흐름:

1. 브라우저에 `http://127.0.0.1:8000/health`를 입력한다.
2. 브라우저가 자기 컴퓨터의 8000번 포트로 연결하고 `/health`에 GET 요청을 보낸다.
3. Uvicorn이 요청을 받아 FastAPI 앱에 전달한다.
4. FastAPI가 등록된 `/health` 경로에 따라 `health()`를 실행한다.
5. 반환한 딕셔너리가 JSON 응답으로 전달된다.
6. 브라우저가 응답을 표시한다. 코드상 예상 내용은 `{"status":"ok"}`이다. 이번 답변에서는 서버를 실행해 확인하지 않았다.

`app = FastAPI()`는 웹 애플리케이션 객체를 만든다. 이 한 줄만으로 네트워크 요청을 받기 시작하지는 않는다. Uvicorn 같은 서버 프로그램이 앱을 실행하고 포트에서 요청을 기다려야 한다.

일반 웹사이트 주소의 예:

```text
https://www.example.com/products?id=3
```

- `https`: 통신 방식.
- `www.example.com`: 호스트 이름. DNS로 IP 주소를 찾는다(캐시된 정보를 쓸 수도 있다).
- 포트 생략: HTTPS 기본 포트 443 사용.
- `/products`: 경로.
- `?id=3`: 쿼리 문자열. 요청에 덧붙이는 값이며 해석 방식은 서버 코드가 정한다.

예시 도메인의 실제 페이지 존재 여부를 확인한 것은 아니다.

웹사이트 구현에서는 HTML이 화면 구조, CSS가 디자인, JavaScript가 화면 동작과 추가 API 요청을 담당한다. FastAPI 같은 백엔드는 요청 처리와 데이터 제공을 담당하며 필요하면 데이터베이스를 이용한다. 백엔드가 HTML을 직접 제공하는 구성도 가능하다.

## 헷갈리기 쉬운 점

- 다른 사람에게 `127.0.0.1:8000`을 알려 주면 그 사람 자신의 컴퓨터로 연결된다. 내 서버를 공개하는 주소가 아니다.
- 외부 공개에는 외부에서 접근 가능한 서버, 네트워크 연결 설정 등이 필요하다. 도메인과 HTTPS도 보통 함께 설정한다. URL 문자열을 바꾸는 것만으로 공개되지는 않는다.
- 같은 컴퓨터 안에서도 브라우저는 클라이언트 역할, Uvicorn과 FastAPI 앱은 서버 역할을 맡을 수 있다.
- 서버 연결 성공과 경로 존재는 다르다. `/health`만 등록하고 `/`를 등록하지 않았다면 루트 경로에서 404를 받을 수 있다.
- 일반적인 HTTP/1.1·HTTP/2 연결은 TCP를 사용하며, HTTPS는 TLS로 보호한다. HTTP/3는 QUIC을 사용한다. 입문 단계에서는 주소 확인 → 연결 → 요청 → 응답 흐름부터 이해하면 된다.
