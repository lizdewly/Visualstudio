## 질문

FastAPI, unicorn, Python, HTML, CSS 같은 간단한 기술로 두 값을 입력받아
사칙연산 결과를 보여주는 직관적인 화면을 만들어 달라. 코드를 검증하고 실행 방법을 알려주며,
전체 요약과 설명을 Readme.md로 정리해 달라. 필요한 피드백은 중간에 질문해 달라.

## 답변

`simple_calculator/` 폴더에 계산기와 실행 안내를 작성했다.
`unicorn`은 FastAPI 실행 서버인 `uvicorn`을 의미한 것으로 해석했다.

HTML 폼이 두 숫자를 GET 요청으로 보내면 FastAPI 함수가 입력을 검사하고 Python에서 계산한다.
계산 결과가 들어간 HTML을 다시 브라우저에 보여주며, CSS가 화면 배치를 담당한다.
서버 실행은 계산기 폴더에서 `.\.venv\Scripts\python.exe main.py`로 하고,
브라우저에서 `http://127.0.0.1:8000`에 접속한다.

`Decimal`을 이용해 십진 소수를 계산한다. 입력은 정수부 최대 12자리와 소수부 최대 10자리이며,
소수는 `0.5`처럼 적는다. 빈 값이나 잘못된 입력은 안내를 표시한다.
두 번째 값이 0이면 나눗셈에만 안내를 표시하고 다른 계산은 수행한다.
처음에는 긴 나눗셈을 유효숫자 50자리에서 반올림하도록 구현했으며, 아래 후속 요청에 따라 5자리로 변경했다.

## 검증

Python 문법 검사를 통과했다. 실제 Uvicorn 서버에 HTTP 요청을 보내는 6개 테스트가 모두 통과했다.
정상 계산, 0 나누기, 입력 오류, HTML 특수 문자 처리, 큰 수와 순환소수, 화면 및 CSS 응답을 확인했다.
예를 들어 `12`와 `3`의 결과는 `15`, `9`, `36`, `4`이고 `0.1 + 0.2`는 `0.3`이었다.
서버 직접 실행도 확인했다. 브라우저 확인 도구 지연으로 화면 배치와 클릭 동작의 시각적 검증은 완료하지 못했다.

## 후속 질문과 답변

### 2026-10-20: 나눗셈 결과를 유효숫자 5자리로 반올림

질문: “순환소수 등 긴 나눗셈 결과는 유효숫자 5자리에서 반올림”

답변: 나눗셈을 수행하기 직전에 Decimal의 `context.prec`를 `5`로 설정했다.
덧셈·뺄셈·곱셈은 기존 50자리 정밀도로 먼저 계산한다. 화면 안내와 README도 갱신했다.
유효숫자는 소수점 아래 자리 수와 다르다. 예를 들어 `2 ÷ 3`은 `0.66667`,
`123456 ÷ 1`은 `123460`이 된다. 기존 ROUND_HALF_EVEN 반올림 규칙을 유지하며,
정확히 중간이면 마지막 남길 숫자가 짝수가 되도록 한다.

### 2026-10-20: 웹 파일이 작동하지 않음

질문: “web file is not working”

답변: 점검 시 8000번 포트에 실행 중인 서버가 없었다. 이 프로젝트의 HTML은
서버가 값을 채워 넣는 화면 틀이므로 파일을 직접 여는 대신 FastAPI 서버를 실행한 뒤
`http://127.0.0.1:8000`으로 접속해야 한다. 사용자가 실제로 파일을 직접 열었는지는 확인하지 않았다.
서버를 실행하고 초기 화면 및 `2 ÷ 3` 계산 요청의 HTTP 200과 `0.66667` 결과를 확인했다.
점검 당시 덧셈·뺄셈·곱셈의 정밀도도 5자리로 설정되어 큰 수 테스트가 실패했으므로,
해당 부분을 50자리로 수정하고 나눗셈은 5자리를 유지했다. 문법 검사와 6개 테스트가 통과했다.
