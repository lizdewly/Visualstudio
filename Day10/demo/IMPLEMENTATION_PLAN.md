# note-demo 최종 구성 계획

- 확정일: 2026-10-27
- 상태: 사용자 구현 승인 반영, 코드 구현 및 로컬 테스트 완료. 상세 실행 결과는 `docs/verification.md` 참조.
- 기준: `PROMPT.md`, `AGENT_PROMPT.md`, 사용자의 최신 지시
- 최신 지시: 기술은 단순하게 구성하고, 데이터를 계속 보존하며, PythonAnywhere 무료 계정에 배포한다.
- 후속 지시로 실제 구현·검증까지 범위가 확장되었다. PythonAnywhere 계정·URL은 없다는 답변을 받았으므로 원격 배포는 수행하지 않고 로컬 WSGI 배포 설정 테스트와 배포 안내를 제공한다.

## 0. 디자인 및 실행 반영 사항

- `design.md`의 cream·stone·action blue, 큰 세리프 제목, pill 버튼, 24px 카드, 여백·hairline·어두운 푸터를 적용했다. 자세한 매핑은 `docs/design-implementation.md`에 기록했다.
- 게시판에 불필요한 상품·장바구니·뉴스레터·silver 상품 무대는 제외하고, 외부 이미지 대신 CSS 저널 삽화를 사용했다.
- 유료 폰트는 포함하지 않고 Georgia/Batang 및 시스템 산세리프로 대체했다. 767px 이하에서 단일 열로 바뀐다.
- 실제 버전·실행 명령은 `requirements.txt`와 `README.md`, 배포 명령은 `docs/deployment-pythonanywhere.md`가 기준이다.
- 로컬 실행 데이터는 `.runtime`에 격리하여 Git·배포 ZIP에서 제외하고, 호스팅에서는 소스 밖 경로를 사용한다.
- 세션 쿠키에는 인증 토큰과 Flask-WTF CSRF 상태만 저장한다. 역할·비밀번호·개인정보는 넣지 않는다.
- 초기 규칙 19개를 조사·선정했고 `seed/masking-rules.json` 및 출처 문서로 제공한다. 로그인 시도 제한용 `auth_attempts` 테이블을 추가했다.

## 1. 확정된 구성과 변경 사항

**Python + Flask + Jinja HTML 템플릿 + 일반 CSS + SQLite**로 하나의 웹앱을 만든다. 브라우저에서 폼을 제출하면 Flask가 처리하고 HTML을 반환한다. 별도의 프런트엔드 빌드나 API 서버를 운영하지 않는다.

| 항목 | 초안 | 최종 결정 |
| --- | --- | --- |
| 화면 | React·TypeScript·Vite | Flask에 포함되는 Jinja 템플릿과 일반 CSS |
| 서버 | Express·TypeScript | Flask 단일 애플리케이션 |
| 요청 방식 | 별도 JSON API | HTML 페이지 조회와 POST 폼 처리 |
| 데이터 | 서버 메모리, 재시작 시 초기화 | 계정·게시글·댓글·마스킹 규칙을 SQLite 파일에 영구 저장 |
| 비밀번호 | 메모리 mock 비교 | Werkzeug 비밀번호 해시 생성·검증 함수 사용 |
| 배포 | 로컬 실행 중심 | PythonAnywhere Web 탭의 WSGI 배포 |
| 초기 데이터 | 시작 시 데모 데이터 생성 | 명시적 초기 설정만 실행, 서비스 시작 시 데이터 변경 금지 |
| 백업 | 미정 | SQLite 백업 명령과 수동 다운로드·복구 절차 제공 |

원본의 mock 인증은 공개 배포 및 계정 영속성 요구와 맞지 않으므로 이번 범위에서 기본 이메일·비밀번호 인증과 해시 저장으로 변경한다. 이는 최신 사용자 지시를 충족하기 위한 설계 변경이며, 원본에 처음부터 해시 저장이 필수였다고 해석하지 않는다. SNS 로그인과 비밀번호 찾기는 계속 향후 기능이다.

`IMPLEMENTATION_PLAN_DRAFT.md`는 이전 검토 이력으로 보존한다. 구현할 때는 이 최종본과 갱신된 `AGENT_PROMPT.md`를 사용한다.

## 2. PythonAnywhere 무료 환경과 적용 방침

공식 문서 확인일: 2026-10-27. 실제 계정의 Web 탭·할당량·만료일은 배포 시 다시 확인한다.

| 확인 사항 | 구성에 반영할 내용 |
| --- | --- |
| 무료 계정은 웹앱 1개, 웹 워커 1개, 디스크 512 MiB, 웹앱 만료 주기 1개월 | 단일 Flask 앱 사용, 파일 첨부 제외, DB·로그·백업 용량 점검, 대시보드에서 기한 내 연장 |
| 신규 무료 계정의 MySQL·예약 작업 제공 제한 | MySQL과 예약 작업에 의존하지 않음; 계정 생성일에 따른 기존 혜택을 전제하지 않음 |
| SQLite는 모든 계정에서 사용 가능하나 공식 문서는 운영 DB로 권장하지 않음 | 소규모 학습·데모 게시판 범위에서 사용, 짧은 쓰기 트랜잭션과 잠금 오류 처리, 트래픽 확대 시 DB·요금제 재검토 |
| Flask는 Web 탭과 WSGI 설정으로 배포 | 콘솔에서 `flask run`을 계속 켜 두는 방식이나 WSGI import 중 `app.run()` 호출 금지 |
| 무료 계정의 외부 통신은 허용 목록 기반 | 마스킹 초기 조사는 개발 단계에서 수행, 배포 앱은 외부 검색·AI API 호출 없이 동작 |

근거: [무료 계정 기능](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/), [DB 지원 범위](https://help.pythonanywhere.com/pages/KindsOfDatabases), [Flask 배포 안내](https://help.pythonanywhere.com/pages/Flask/), [외부 통신 제한](https://help.pythonanywhere.com/pages/403ForbiddenError).

데이터 보존은 DB 파일을 삭제·덮어쓰지 않는 애플리케이션 설계와 백업 운영을 의미한다. 무료 호스팅의 영구 가동이나 무기한 보관을 보장하는 의미는 아니다. 서비스 만료 관리와 데이터 백업은 별개로 수행한다.

## 4. 최소 기술 및 코드 구성

| 구성 | 용도 |
| --- | --- |
| Flask | 라우팅, 요청 처리, 세션 쿠키, 오류 처리 |
| Jinja·Werkzeug | Flask와 함께 사용하는 HTML 렌더링·비밀번호 해시 처리 |
| Python 표준 `sqlite3` | DB 연결, SQL, 트랜잭션, 백업; 별도 ORM은 도입하지 않음 |

| 표준 `unittest`와 Flask test client | 마스킹·권한·폼·데이터 보존 자동 검증 |

의존성 버전은 구현 시 PythonAnywhere에서 선택 가능한 Python 버전과 로컬 환경의 공통 버전에 맞춰 검증하고 `requirements.txt`에 고정한다. 화면은 서버 렌더링으로 완결하고 JavaScript가 없어도 핵심 조회·작성 동작을 사용할 수 있게 한다.

## 5. 저장 정책과 데이터 모델

PythonAnywhere DB 경로 예시는 `/home/<username>/note-demo-data/note-demo.sqlite3`이다. `<username>`은 실제 계정명으로 바꾼다. DB 위치는 `DATABASE_PATH` 설정으로 전달하고 절대 경로로 처리한다. 로컬 개발과 테스트 DB는 별도 파일을 사용한다.

| 테이블 | 주요 필드 | 규칙 |
| --- | --- | --- |
| users | id, email, nickname, password_hash, role, created_at | 정규화 이메일 UNIQUE, role은 USER/ADMIN |
| sessions | token_hash, user_id, expires_at | 임의 토큰 원문은 쿠키에, 해시는 DB에 저장; 비밀번호 저장 금지 |
| posts | id, author_id, title_raw, content_raw, created_at, updated_at | 작성자는 서버 인증 상태에서 결정 |
| comments | id, post_id, author_id, content_raw, created_at | 게시글 삭제 시 연결 댓글 함께 삭제 |
| masking_rules | id, keyword, normalized_keyword, created_at | 정규화 키워드 UNIQUE, 빈 규칙 거부 |
| schema_meta | version | 스키마 버전 기록 및 변경 이력 관리 |

- 연결마다 외래키 검사를 활성화하고 요청 종료 시 연결을 닫는다. 매개변수 바인딩 SQL을 사용한다.
- 게시글 삭제와 댓글 삭제는 외래키 CASCADE 및 하나의 트랜잭션으로 처리한다. 쓰기는 짧게 유지하고 DB 잠금 대기와 실패 안내를 둔다. WAL 등 저장소 특성에 민감한 튜닝은 기본으로 강제하지 않는다.
- 초기 스키마 생성은 명시적 CLI 명령으로 수행하고 반복 실행해도 기존 데이터를 지우지 않는다. 스키마 변경은 별도 버전 변경 작업으로 처리하며 변경 전 백업한다.
- 서버 시작·모듈 import·Reload 시 초기화·DROP·데모 데이터 재삽입·규칙 덮어쓰기를 하지 않는다.
- 초기 규칙은 최초 설정 단계에서만 명시적으로 가져온다. 관리자가 삭제한 규칙을 재시작 시 복원하지 않는다.
- 데모 계정·21개 게시글은 테스트 DB용 fixture로만 만들고 공개 배포 DB에는 자동 삽입하지 않는다.
- 이메일·닉네임·본문 등 입력 상한은 코드 상수와 폼에서 일치시킨다. 기본안은 닉네임 30자, 제목 200자, 본문 20,000자, 댓글 2,000자, 키워드 100자이다.

## 6. 회원 및 권한 정책

가입 시 이메일 형식·중복·닉네임·비밀번호를 검사한다. 이메일은 앞뒤 공백 제거와 대소문자 정규화 후 중복 검사한다. 비밀번호는 공백을 임의로 제거하지 않고 8~128자 정책을 안내한다. 저장에는 Werkzeug의 `generate_password_hash`, 검증에는 `check_password_hash`를 사용한다. 직접 만든 암호 알고리즘이나 평문 저장은 사용하지 않는다. 근거: [Werkzeug 보안 함수](https://werkzeug.palletsprojects.com/en/stable/utils/#werkzeug.security.generate_password_hash).

로그인 성공 시 새 임의 세션 토큰을 발급하고 서버 DB에는 토큰 해시와 만료 시각을 저장한다. Flask 서명 쿠키에는 해당 토큰만 넣고 비밀번호·역할·개인정보를 넣지 않는다. 요청마다 DB에서 세션과 현재 사용자 역할을 확인한다. 세션 유효기간은 24시간으로 시작하고 만료 시 재로그인을 안내한다.

로그아웃은 현재 세션 DB 행 삭제와 쿠키 제거를 함께 수행한다. 이전 쿠키를 재사용해도 해당 세션으로 인증되지 않아야 한다. 로그인 만료와 데이터 보존은 별개이며 재로그인하면 기존 글과 계정이 유지된다.

`SECRET_KEY`는 한 번 생성해 소스 밖 비밀 설정에 보관하고 Reload 때마다 새로 만들지 않는다. HTTPS 배포에서는 HttpOnly·Secure·SameSite=Lax 쿠키를 사용한다. 가입·로그인·로그아웃을 포함한 모든 POST 폼에 CSRF 검증을 적용한다. 사용자 입력은 Jinja 자동 이스케이프를 유지하고 `safe` 처리하지 않는다. 근거: [Flask 보안 지침](https://flask.palletsprojects.com/en/stable/web-security/).

관리자는 콘솔 CLI 명령에서 이메일·닉네임과 숨김 비밀번호 입력으로 생성한다. 고정 기본 관리자 비밀번호를 코드·문서·초기 데이터에 넣지 않는다. 회원가입에서 역할을 선택하거나 변경할 수 없다. 공개 페이지에 비밀번호 해시·세션·원문 DB를 노출하지 않는다.

| GET `/posts?page=1` | 제목만 있는 게시글 목록 및 페이지 버튼 | 누구나 |
| GET/POST `/posts/new` | 제목·내용 작성 | 로그인 |
| GET `/posts/<id>` | 마스킹된 제목·내용·댓글, 댓글 작성 폼 | 조회는 누구나 |
| GET/POST `/posts/<id>/edit` | 본인 원문 편집·저장 | 작성자만 |
| POST `/posts/<id>/delete` | 삭제 확인 후 게시글·댓글 삭제 | 작성자만 |
| POST `/posts/<id>/comments` | 댓글 저장 | 로그인 |
| GET/POST `/admin/masking` | 키워드 목록·추가 | 관리자만 |
| POST `/admin/masking/<id>/delete` | 키워드 삭제 | 관리자만 |

성공한 POST는 리다이렉트 후 GET으로 결과를 표시한다. 데이터 변경은 GET으로 처리하지 않는다. 검증 실패 시 해당 폼과 오류를 표시하되 비밀번호는 재표시하지 않는다. 서버에서 권한을 다시 검사하여 URL·폼 직접 호출로 우회할 수 없게 한다.

밝은 배경, 단일 본문, 한국어 라벨, 키보드 접근 가능한 폼을 사용한다. 상단에는 서비스명·회원 메뉴·로그인 닉네임·관리자 진입점을 제공한다. 게시글 목록의 각 행에는 제목만 표시한다. 페이지 버튼과 글쓰기 버튼은 별도 영역에 둔다.

목록은 `created_at DESC, id DESC`, 페이지당 10개이다. 음수·문자 등 잘못된 page는 첫 페이지로 보정하고 범위 초과는 마지막 유효 페이지로 보정한다. 0건이면 1페이지의 빈 상태를 표시하고 이동 버튼을 비활성화한다. 삭제 후 원래 목록 페이지로 돌아가되 유효한 페이지로 보정한다.

## 8. 댓글 및 마스킹

댓글은 게시글별 작성·조회만 제공한다. 공백 댓글은 거부하고 댓글 작성자도 서버 인증 상태에서 결정한다. 댓글 수정·삭제·대댓글은 추가하지 않는다.

마스킹은 키워드 리터럴 매칭으로 구현한다. 관리자가 정규식을 입력하는 기능은 제외한다. 특수문자는 문자 그대로 처리하며 영문 대소문자는 구분하지 않는다. 한글은 부분 문자열 일치를 적용하되 짧거나 일상 표현을 과도하게 막는 키워드는 초기 선정에서 제외한다.

원문에서 일치한 구간을 찾고 겹치는 구간을 병합한 후 각 구간을 `***`로 치환한다. 치환 결과를 다시 검색하지 않는다. 원문은 SQLite에 저장하고 화면 렌더링 직전에 현재 DB 규칙으로 제목·내용·댓글을 변환한다. 규칙 변경 후 다음 조회부터 기존 글에도 반영한다. 닉네임은 마스킹 범위에 넣지 않는다.

일반 HTML 응답의 숨김 필드·스크립트·속성에도 원문을 함께 넣지 않는다. 작성자 본인 편집 화면에서만 원문을 전달한다. 관리자 규칙 페이지를 제외한 사용자 화면에 전체 규칙 목록을 불필요하게 전달하지 않는다.

초기 표현 목록은 2026-10-27 공개 원자료를 직접 조회하여 19개를 선정했고 `docs/masking-sources.md`에 출처·조회일·선정 이유·오탐 사례를 기록했다. 개발 환경에서 조사한 결과 파일을 배포하며 앱 실행 때 인터넷 검색이나 자동 갱신을 하지 않는다.

## 9. 배포 및 데이터 보존 절차

다음은 구현 후 수행할 배포 절차이며, 현재 실행한 작업은 아니다.

1. PythonAnywhere에서 사용 가능한 Python 버전을 확인하고 같은 버전의 virtualenv에 `requirements.txt`를 설치한다.
2. 소스는 `/home/<username>/note-demo`, 데이터·비밀 설정은 `/home/<username>/note-demo-data`처럼 분리한다. Windows 경로나 상대 작업 디렉터리에 의존하지 않는다.
3. 소스 밖 설정 파일에 안정적인 `SECRET_KEY`, DB 절대 경로, 배포 모드를 저장하고 계정 소유자만 읽도록 권한을 설정한다. WSGI 진입점이 명시적으로 이 설정을 로드하게 하여 Bash 환경변수 상속에 의존하지 않는다.
4. 초기 DB 생성, 초기 규칙 가져오기, 관리자 생성을 명시적 CLI 명령으로 1회 수행한다. DB 경로를 확인하고 데이터 삭제 명령은 배포 절차에 넣지 않는다.
5. Web 탭에서 Manual configuration과 virtualenv와 동일한 Python 버전을 선택한다. WSGI 파일에서 프로젝트 경로를 추가하고 `create_app()` 결과를 `application`으로 노출한다.
6. `/static/`만 `app/static/`에 매핑한다. 프로젝트 루트·데이터 디렉터리·설정·백업 파일은 정적 경로에 매핑하지 않는다.
7. 디버그를 끄고 HTTPS를 사용한다. Web Reload 후 오류 로그와 주요 화면·쓰기·로그인 동작을 확인한다.
8. 배포 계정으로 글·댓글·규칙을 저장하고 Web Reload 후 다시 로그인해 동일한 데이터와 권한이 유지되는지 확인한다.
9. 코드 업데이트 시 DB를 포함하지 않는다. 테스트용 DB를 업로드하거나 기존 DB 경로에 복사하지 않는다. 스키마 변경이 있으면 백업 후 명시적으로 적용한다.

**백업:** Python `sqlite3.Connection.backup()` 기반 CLI를 제공해 일관된 별도 백업 DB를 생성한다. 업데이트 전 및 주 1회 수동 실행·다운로드를 운영 기본으로 문서화한다. 무료 예약 작업을 전제하지 않는다. 다운로드한 백업은 계정 정보와 원문이 포함된 비공개 파일로 보관한다. 서버에 백업을 무제한 누적하지 않도록 보관 개수를 제한한다.

**복구:** 쓰기 요청이 차단된 유지보수 상태에서 현재 DB도 별도 보존한 뒤 백업 파일의 무결성을 확인하고 지정 DB로 복구한다. 재연결·Reload 후 계정·게시글·댓글·규칙을 확인한다. 복구 백업에 남은 과거 세션은 모두 제거해 로그아웃 상태로 시작한다. 복구 연습은 별도 테스트 DB에서 먼저 수행한다.
